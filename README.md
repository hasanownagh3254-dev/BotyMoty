# BotShop — ربات‌های دانلود اینستاگرام / یوتیوب / تیک‌تاک / پینترست

## ۱. اجرای همه‌ی ربات‌ها روی سرور خودت (Render)

1. این پوشه را در یک ریپازیتوری GitHub آپلود کن.
2. یک اکانت رایگان در [render.com](https://render.com) بساز و یک **Web Service** جدید از روی همین ریپو بساز.
3. تنظیمات Render:
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `python main.py`
4. در بخش **Environment** روی Render، چهار متغیر زیر را با توکن واقعی هر ربات پر کن
   (توکن را از [@BotFather](https://t.me/BotFather) در تلگرام بگیر):
   - `INSTA_BOT_TOKEN`
   - `YOUTUBE_BOT_TOKEN`
   - `TIKTOK_BOT_TOKEN`
   - `PINTEREST_BOT_TOKEN`
5. سرویس را Deploy کن. چند دقیقه بعد هر چهار ربات باید در تلگرام جواب بدهند.
6. برای اینکه سرویس رایگان Render نخوابد، آدرس سرویس را در [uptimerobot.com](https://uptimerobot.com) (رایگان) هر ۵ دقیقه پینگ کن.

## ۲. مهم‌ترین محدودیت‌ها (قبل از فروش حتماً بخوان)

- **حجم فایل:** تلگرام اجازه نمی‌دهد رباتی فایل بالای ۵۰ مگابایت بفرستد. ویدیوهای طولانی/کیفیت بالا ممکن است رد شوند (کد این را با پیام خطا به کاربر اطلاع می‌دهد، کرش نمی‌کند).
- **شکستن گاه‌به‌گاه دانلودر:** اینستاگرام/تیک‌تاک/یوتیوب مرتب روش کارشان را عوض می‌کنند و `yt-dlp` گاهی از کار می‌افتد تا آپدیت بشود. این یعنی هر از گاهی باید دستور `pip install -U yt-dlp` را در `requirements.txt` بروزرسانی و دوباره Deploy کنی.
- **منابع پلن رایگان Render:** فقط ۵۱۲ مگابایت رم و توان پردازشی محدود. اگر چند نفر هم‌زمان ویدیوی سنگین دانلود کنند ممکن است سرویس کند شود یا ری‌استارت بخورد. برای فروش جدی، در نهایت پلن پولی Render ($7/ماه به بالا) پایدارتر است.
- **محدودیت پینترست:** خیلی از پین‌ها فقط عکس هستن نه ویدیو. اگر کاربر لینک یک پین بدون ویدیو بفرسته، ربات با پیام خطای عمومی جواب می‌ده (نه کرش).
- **ریسک ToS پلتفرم‌ها:** دانلود از اینستاگرام/تیک‌تاک معمولاً ناقض قوانین همان پلتفرم است. یعنی ممکن است بدون هشدار قبلی، روش دانلود مسدود شود. این را در تبلیغ محصول شفاف بگو تا مشتری انتظار گارانتی همیشگی نداشته باشد.

## ۳. حالت دمو (برای این‌که خریدارها قبل از خرید امتحان کنن)

هر ۴ ربات از یک محدودیت **اختیاری** پشتیبانی می‌کنن: هر کاربر تلگرام فقط N بار می‌تونه دانلود موفق بگیره، بعدش پیام «برای خرید نسخه‌ی نامحدود پیام بده» می‌بینه.

برای فعال‌کردنش، این دو متغیر محیطی رو در Render (روی سرویسی که **خودت** برای معرفی/دمو اجرا می‌کنی، نه سرویس مشتری) اضافه کن:
- `FREE_USE_LIMIT=2` (یا هر عددی که بخوای)
- `SELLER_CONTACT=@your_telegram_username`

اگر این دو متغیر را نذاری یا خالی بذاری، ربات کاملاً **نامحدود** کار می‌کنه — دقیقاً همون چیزی که وقتی مشتری واقعی می‌خره باید بهش بدی (بدون این دو متغیر در render.yaml مشتری، پس نگرانِ نشتِ محدودیت به نسخه‌ی فروخته‌شده نباش).

⚠️ شمارش دفعات استفاده در یک فایل کنار کد (`usage_data.json`) نگه‌داری می‌شه، نه دیتابیس واقعی. روی پلن رایگان Render اگه سرویس کاملاً Redeploy یا ری‌استارت بشه، ممکنه این فایل پاک بشه و شمارش از صفر شروع بشه. برای جلوگیری از سوءاستفاده‌ی جدی (نه فقط تست معمولی) کافی نیست، ولی برای دموی ساده مشکلی نداره.

## ۴. روش پیشنهادی برای فروش: دیپلوی مستقیم روی حساب Render خود مشتری

پوشه شامل `app.py` و `render.yaml` است — یک نسخه‌ی تک‌رباتی که مشتری با وارد کردن دو متغیر (`PLATFORM` و `BOT_TOKEN`) دقیقاً همان رباتی را که خریده اجرا می‌کند، بدون دیدن یا لمس هیچ کدی.

**مراحل (یک‌بار برای همیشه):**
1. این پروژه را در یک ریپازیتوری **عمومی (public)** روی GitHub خودت آپلود کن (Render برای دیپلوی مستقیم به ریپوی عمومی نیاز دارد، مگر مشتری گیت‌هاب خودش را وصل کند).
2. این لینک را با آدرس ریپوی خودت بساز:
   ```
   https://render.com/deploy?repo=https://github.com/USERNAME/REPO_NAME
   ```

**مراحل (هر بار که یک ربات می‌فروشی):**
1. همین لینک بالا را برای مشتری بفرست.
2. مشتری با ایمیل/گیت‌هاب **خودش** روی Render وارد یا ثبت‌نام می‌کند (تو هیچ‌وقت ایمیل یا پسورد او را نمی‌بینی).
3. Render از او دو مقدار می‌خواهد:
   - `PLATFORM` → یکی از `instagram` / `youtube` / `tiktok` / `pinterest`
   - `BOT_TOKEN` → توکنی که خودش از @BotFather گرفته
4. مشتری روی Deploy می‌زند و چند دقیقه بعد ربات زیر حساب خودش، با منابع خودش، بالا می‌آید.

با این روش هیچ ظرفیتی از حساب تو مصرف نمی‌شود، هیچ رمز/ایمیلی رد و بدل نمی‌شود، و اگر یکی از ربات‌های فروخته‌شده کرش کند یا محدود شود، ربات‌های دیگر (مال تو یا سایر مشتری‌ها) اصلاً تحت‌تأثیر قرار نمی‌گیرند.

## ۵. روش جایگزین (اگر نمی‌خواهی کد را عمومی روی GitHub بگذاری)
- یک ریپوی **خصوصی** بساز و مشتری را به‌عنوان Collaborator اضافه کن، یا کد را به‌صورت زیپ برایش بفرست تا خودش در GitHub خودش آپلود کند و از همان‌جا به Render خودش وصل کند (بدون نیاز به دکمه‌ی Deploy).
- این کمی دستی‌تر است ولی باز هم کاملاً روی حساب خود مشتری اجرا می‌شود.

## ۶. چطور یک ربات را «بفروشی» بدون این‌که به بقیه آسیب بزنی

**روش امن و پیشنهادی (تحویل کامل و مستقل به خریدار):**
هر ربات را جدا از بقیه به خریدار بده تا خودش روی اکانت GitHub/Render خودش اجرا کند. این‌طوری بعد از فروش، هیچ وابستگی‌ای به سرور تو ندارد و اگر ربات‌های دیگرت مشکلی پیدا کنند، ربات خریدار خاموش نمی‌شود.

برای فروش **فقط ربات اینستاگرام** مثلاً، این فایل‌ها را در یک پوشه/زیپ جدید به خریدار بده:
```
core/common.py
core/bot_factory.py
core/usage_limiter.py
core/instagram.py
bot_insta.py          → این را main.py صدا بزن یا مستقیم اجرا کن
keep_alive.py
requirements.txt
.env.example
```
(کد اصلاً دست‌خوردنی ندارد — خریدار فقط توکن خودش را از BotFather می‌گیرد و در `.env` یا Environment Variables روی Render خودش می‌گذارد.)

**روش دوم (مدل اشتراکی/SaaS):**
اگر می‌خواهی خودت میزبانی کنی و ماهانه از مشتری پول بگیری، همان یک سرویس روی Render نگه‌دار و فقط توکن هر ربات را در Environment Variables عوض کن. توجه: این یعنی همیشه پشتیبانی و نگه‌داری آن با توست، و اگر مشتری پول ندهد باید توکنش را خودت حذف/غیرفعال کنی.

## ۷. تست محلی (اختیاری، قبل از آپلود روی Render)
```bash
pip install -r requirements.txt
cp .env.example .env   # سپس توکن‌ها را داخلش بگذار
python main.py
```
